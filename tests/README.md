# Warer 后端测试

本目录包含后端计算引擎的持久化测试套件。

## 运行

```bash
# 方式 1: 直接运行
cd backend
python tests/test_engine.py

# 方式 2: 作为模块运行
cd backend
python -m tests.test_engine
```

## 覆盖范围

| 套件 | 内容 | 用例数 |
|------|------|--------|
| `[1] 基础计算 (basic)` | 常规代数、三角、对数、积分、求导、求解、化简 | ~25 |
| `[2] 边界用例 (boundary)` | 零、大数、特殊符号、嵌套函数、空输入、矩阵、定积分 | ~25 |
| `[3] 错误用例 (error)` | 语法、括号、矩阵、求解、极限、泰勒、ODE、方程组错误 | ~30 |
| `[4] 复杂表达式 (complex)` | 多层括号、嵌套函数、复杂方程/矩阵/泰勒/ODE/定积分/方程组 | ~20 |
| `[5] 性能用例 (performance)` | 中等规模展开/化简/积分/因式分解、大矩阵 | ~5 |

## 设计原则

1. **不要删除本目录** —— 这是回归测试的基线，每次修改引擎都应确保所有测试通过。
2. **可独立运行** —— 测试脚本不依赖 pytest/unittest，可直接用 `python` 执行。
3. **分类清晰** —— 输出中每个失败用例都会标注类别（如 `err.syntax`），便于定位。
4. **性能监控** —— 末尾会列出 Top-5 慢查询。
5. **错误类型严格匹配** —— `expect_error` 断言错误的 `type` 字段，不能笼统地"应该报错"。

## 添加新用例

在对应的 suite 函数中追加 `expect_ok(...)` 或 `expect_error(...)` 即可：

```python
def suite_basic() -> None:
    expect_ok("basic.my_feature", "myfunc(x)", "x")
```

如果新功能不属于已有类别，可以新建一个 suite 函数并在 `main()` 中调用。
